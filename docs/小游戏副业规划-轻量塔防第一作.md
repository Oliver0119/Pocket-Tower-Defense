# 微信小游戏副业规划 + 轻量塔防第一作开发方案

> 面向：Java 工程师（有小程序开发经验）｜投入：10~15 小时/周｜技术栈：Cocos Creator 3.x + TypeScript
> 更新日期：2026-08-28

---

## 第一部分：副业总体规划

### 1. 市场格局速览（2026.8）

微信小游戏用户已破 10 亿，畅销榜 Top 100 品类分布与个人开发者适配度：

| 品类 | 榜单表现 | 核心壁垒 | 个人适配度 | 说明 |
|---|---|---|---|---|
| **塔防射击** | 12 款在榜，《向僵尸开炮》长期第 1 | 数值平衡、怪物 AI、买量 | ⭐⭐⭐⭐ | 热度最高且持续有新品突围（《城主别慌张》新进 Top 20） |
| 模拟经营 | 三强占 Top 10（《我的花园世界》《浪漫餐厅》） | 数值策划、内容更新 | ⭐⭐⭐ | 爆发力强但长线运营重 |
| 休闲消除 | 单机可跑，靠创新破圈 | 玩法创新 | ⭐⭐⭐⭐⭐ | 开发量最小，适合练手第一作 |
| 放置挂机 | 用户基数大 | 深度数值体系 + 长线运营 | ⭐⭐ | 依赖买量，个人难起量 |
| SLG / MMO / 棋牌 | 头部壁垒极高 | 资本 + 买量 + 团队 | ⭐ | **不要碰** |

**关键结论**：塔防赛道体量大、变体空间多、单体爆款门槛相对低，是"轻量变体 + 广告变现"路线的最佳选择。

### 2. 变现模型

个人开发者的主路径是**广告变现**（内购需要付费点设计 + 运营，个人门槛过高）：

```
月收益 ≈ DAU × 人均激励视频观看次数 × eCPM / 1000 × 30
```

收益测算表（取 eCPM = 30 元，人均观看 3 次）：

| DAU | 人均观看/日 | 日收益 | 月收益（估算） |
|---|---|---|---|
| 100 | 3 | ~9 元 | ~270 元 |
| 500 | 3 | ~45 元 | ~1,350 元 |
| 1,000 | 3 | ~90 元 | ~2,700 元 |
| 5,000 | 4 | ~180 元 | ~5,400 元 |
| 20,000 | 4 | ~720 元 | ~21,600 元 |

**解读**：DAU < 1000 阶段收益是零花钱级别，真正有意义的是跑通"开发→上架→起量"全流程并积累技术资产；DAU 5000+ 才值得谈副业收入。**留存（次留 ≥ 20%）决定平台是否推流，比变现设计更重要。**

广告类型优先级：**激励视频 > 插屏 > 原生模板/Banner**。只接一种就接激励视频（eCPM 最高、体验破坏最小）。

### 3. 上架合规清单（前置条件，越早启动越好）

| 事项 | 说明 | 周期 | 费用 |
|---|---|---|---|
| 小游戏账号注册 | mp.weixin.qq.com，个人主体可发小游戏（类目选"小游戏-休闲益智"） | 1~3 天 | 免费（个人 300 元认证可选） |
| **软件著作权** | 上架审核/备案的关键材料。可自行申请（周期 1~3 个月）或走加急代理 | 1~3 个月 | 自行 ~300 元 / 代理加急 ~500~1500 元 |
| 游戏备案 | 2024 起新规：小游戏需备案。纯广告单机无内购**通常不需要版号**，但需完成备案 | 随审核流程 | 免费 |
| 流量主开通 | 三条路任选：① 累计 UV > 500；② 开通游戏圈 + 有效活跃 + 发 5 篇官方帖（体验版即可操作，**推荐**）；③ 已有变现小程序 | 3~7 天 | 免费 |
| 财务结算 | 个人绑定银行卡，按个税征收；量大后建议注册个体户走公对公 | — | — |

> ⚠️ 软著是整个时间线上最长的一环，**第一周就应提交申请**，与开发并行。

### 4. 副业矩阵路线图（长期策略）

```
第 1~2 月   第一作 MVP（轻量塔防）→ 上架 → 种子用户 → 数据验证（次留/广告观看率）
第 3 月     复盘：保留核心循环，砍掉无效设计；同时开通流量主、观察自然量
第 4~6 月   同引擎换皮矩阵：复用核心代码框架，2~3 周出一款变体（换题材/换玩法微创新）
            平台算法对新游戏会给种子流量，矩阵策略 = 分散单款风险
第 6 月+    找到跑出的那款 → 加码内容更新与广告优化；没跑出的款维持低频维护
```

**核心心法**：单款天花板低不要紧，矩阵 + 快速迭代才是个人副业的正确姿势。每一作都要沉淀可复用的代码框架和美术素材库。

## 第二部分：第一作开发方案（轻量塔防）

### 1. 竞品拆解

| 产品 | 核心循环 | 可借鉴 | 应避开 |
|---|---|---|---|
| 《向僵尸开炮》（榜 1） | 塔防 + 击杀升级 + **技能三选一（Roguelike）** + 关卡推进 | 技能三选一极大提升复玩性；每波结束的即时爽感 | 重度数值养成、多英雄系统 |
| 《保卫向日葵》 | 经典塔防 + 植物合成升级 | 波次结构清晰、单手可玩 | 站位策略过深 |
| 《城主别慌张》（新进 Top 20） | 塔防 + **古风城市管理题材差异化** + 技能推荐降低卡关 | 题材差异化避开正面竞争；新手推荐保底 | 门客养成体系 |

**提炼出的可单人落地骨架**：单屏极简塔防 + 波次推进 + 击杀掉金币 + 升级塔 + **每波 Roguelike 三选一技能** + 死亡复活（广告点）。

### 2. 差异化定位

- **不做**：向僵尸开炮的换皮（题材红海）、需要大量立绘的重题材
- **做**：选择非末世/非僵尸的低竞争题材（如 2026 年在榜的《城主别慌张》证明古风/治愈题材可突围），美术用 AI 生成 + 轻量素材（卡通、低细节）
- **操作极简**：一键布塔/自动攻击，纯"看 + 选"的轻策略，通勤场景单手可玩

### 3. MVP 玩法设计

**核心循环**：

```
进入关卡 → 摆塔（有限金币）→ 波次战斗（自动）→ 击杀得金币/升级
    ↑                                        ↓
    └──── 失败 → 看广告复活 or 重开 ← 通过波次 → Roguelike 三选一 → 下一波
```

**MVP 功能清单（第一版只做这些）**：

| 模块 | 内容 |
|---|---|
| 塔系统 | 3 种基础塔（单体快攻 / 范围减速 / 重击慢速），每塔 3 级升级 |
| 敌人 | 3 种（普通 / 快速 / 坦克），血量随波次按曲线增长 |
| 波次 | 每关 10 波，共 20 关（前 5 关教学难度） |
| Roguelike | 波次结束三选一：攻速+10%、暴击率+5%、金币+20% 等（池子 8~10 条） |
| 经济 | 击杀掉金币 → 造塔/升级；失败不清空（降低挫败） |
| 存档 | 微信云开发 or 本地 storage 记录关卡进度 |

**数值框架（起点，上线后调）**：

- 敌人血量：`HP(n) = 50 × 1.18^n`（n 为波次），金币产出：`drop(n) = 3 + n × 0.8`
- 塔 DPS 成本效率：单体塔 DPS/金币 ≈ 减速塔 × 0.7 ≈ 重击塔 × 1.4（保证各有用武之地）
- 目标：普通玩家第 5~7 波开始吃力，卡关即触发"看广告复活"的自然需求

### 4. 技术架构（Cocos Creator 3.x + TS）

```
assets/
├── scripts/
│   ├── core/          # GameManager, EventCenter, ObjectPool, SaveManager
│   ├── battle/        # EnemyManager, TowerSystem, BulletSystem, WaveController
│   ├── ui/            # HUD, SkillChoosePanel, ResultPanel, RevivePanel
│   └── platform/      # AdService(广告统一封装), ShareService, Analytics
├── prefabs/           # 塔/敌人/子弹/特效预制体（对象池复用）
└── scenes/            # Home(主界面), Battle(战斗)
```

**给你的 Java 经验映射**：

- `EventCenter` ≈ 事件总线（类似 Spring 的 ApplicationEvent）
- `AdService` 单例统一管理三个广告位生命周期，TS 无 Checked Exception，注意 `wx.createRewardedVideoAd` 的回调只注册一次（onClose 重复注册 = 重复发奖励的经典 Bug）
- 对象池（敌人/子弹/特效）是性能生命线，避免 GC 卡顿

**关键技术规范**：

- 首包 ≤ 4MB：纹理压缩（ASTC/ETC2）、远程资源用分包/CDN 加载
- 逻辑与渲染分离：数值计算不依赖节点遍历
- 真机测试为准：开发者工具的广告/性能数据都不可信

### 5. 广告点位设计（合规优先）

| 点位 | 类型 | 设计 |
|---|---|---|
| 失败复活 | 激励视频 | **最高优先**。按钮文案"立即复活"而非"看广告"；每局限 1 次 |
| 双倍金币 | 激励视频 | 结算页"看视频金币 ×2"，观看率稳定的第二点位 |
| 抽技能重选 | 激励视频 | 三选一不满意可看广告重抽（Roguelike 玩法天然契合） |
| 关卡间隙 | 插屏 | 冷却 ≥ 2~3 分钟，随机概率弹出，**一局 ≤ 3 次** |

**合规红线**（违反会被关停广告权限甚至封号）：
🚫 强制看广告进游戏｜🚫 广告按钮与操作按钮重叠｜🚫 刷量｜🚫 一局插屏 > 3 次

### 6. 上架执行时间线（与开发并行）

```
第 1 周    注册小游戏账号 + 提交软著申请（最长前置，立即启动）
第 1~4 周  Cocos Creator 学习 + MVP 开发（见里程碑文档）
第 5 周    接入 AdService（体验版调试广告）+ 开通游戏圈走流量主条件②
第 6 周    种子用户（朋友圈/同事）→ 观察次留，快速调数值
第 7~8 周  软著到位后提交审核 → 备案 → 正式发布
```

**种子用户生死线**：平台给首批 100 个自然用户，次留 ≥ 20% 才会继续推流。前期宁可晚开广告，也要先把留存做上去。

## 附：收益预期管理（实话）

- 前 3 个月按 **月均几百元** 预期，这个阶段的价值是跑通流程 + 沉淀框架
- 矩阵第 3~4 款起，若有一款次留 > 25% 且自然量稳定，才有月入数千的可能
- 全程不需要版号（无内购），最大成本是软著 ~300 元 + 你的时间
